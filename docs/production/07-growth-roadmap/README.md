# Growth roadmap

These are proposals, not claims of national coverage, traffic, revenue or service levels.

## Stage 0: reliable operation

Complete hosting eligibility, actual Neon branches/grants/restore, backend source/runtime, minor/privacy onboarding, abuse protection, staffed moderation and staged flow acceptance. Record versions and rollback evidence. Keep checkout/ads paused until separately accepted.

## Stage 1: trust and clarity

Add password verification/recovery, a reviewer queue with private media and immutable decisions, editorial correction/permission records and clear support states. Keep access owner/operator scoped. Use observed task failures before redesigning the low-dependency architecture.

## Stage 2: reservation operations

Add validated event times/timezones, capacity, party size, organiser cancellation and waitlist rules when hosts need them. Require atomic seat allocation and duplicate/race tests. Introduce opt-in verified email through a budgeted outbox with idempotency/retries/preferences; do not send email inside DB transactions. Existing requests remain one-person, host-confirmed and dashboard-only.

## Stage 3: Study usefulness

Evaluate chapter accuracy with educators, improve accessible diagrams and error reporting, and establish language/guardian/school workflows. Benchmark queue fairness and synthetic load before changing paid tiers or model budgets. Do not market formative AI scoring as certified examination grading.

## Stage 4: richer local discovery

Consider organiser verification with explicit meaning/appeals, local languages, spelling aliases and evidence-based relevance. Build locality pages only with real differentiated content. H3 distance estimates are not navigation/travel-time promises. A paid map SDK is unnecessary until a real map requirement exists.

## Stage 5: scale from measurements

Watch aggregate DB connections, active notices, media bytes, query latency, model budget and review backlog. Move private media to authorised object storage only when database pressure warrants it; preserve approval/withdrawal checks. Add indexing/search services or external workers after a demonstrated bottleneck. Operate retention/pagination before raising caps.

## Stage 6: new business capabilities

Pilot labelled fixed-price sponsorships after approval. Evaluate attendance, recurring events and merchant reporting with honest definitions. Ticket sales, venue payment handling, delivery or verified-news claims change obligations and architecture; treat each as a separate product decision.

## Prioritise explicitly

For every proposal record user problem, evidence, expected benefit, cost, privacy/safety effect, owner, acceptance test and rollback. Prefer changes that reduce failed tasks/support and preserve trust rather than copying competitors indiscriminately.
