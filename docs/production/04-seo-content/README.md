# SEO and editorial reach

## 1. Establish canonical ownership

Use core, Study and marketplace hosts consistently. Configure the portal URL suffixes from the deployment guide and inspect actual canonicals/redirects. Reachable duplicate host/path URLs must identify one preferred page. Do not collapse every portal canonical to Home.

## 2. Verify search accounts

Verify DNS/domain ownership in Google Search Console and Bing Webmaster Tools using operator accounts. Submit the public sitemap and inspect representative URLs, indexing and security reports. No verification/submission was performed by this audit. Indexing or first-page ranking is not guaranteed.

## 3. Separate public from private

Discoverable surfaces: useful landing/curriculum pages, original guides, published Journal notes and approved/unexpired/unblocked notices. Private papers/answers, dashboards, auth, posting/report forms and APIs have robots exclusions/noindex headers. Preview robots blocks crawling and its sitemap is empty; use deployment authentication too.

The sitemap includes at most 500 current notice IDs and 500 published Journal slugs, with a five-second curriculum fetch deadline and static fallback. Add paginated sitemap indexes when real inventory warrants them. Withdrawn/expired content leaves discovery. Dummy articles remain noindex/out of sitemap; interactive dummy listings are explicitly fictional and non-bookable.

## 4. Publish useful original work

Study: teacher-reviewed chapter explanations, practice routines, source provenance and formative-feedback limitations. Nearby: real venue, locality/city, calendar timing, total charges/conditions and organiser responsibilities. An AI safety verdict is not business verification.

Before publishing factual news, require attributable sources, rights/licences, dates, editor review and correction handling. The current product is learning notes and local notices. Do not scrape/rewrite competitors or generate hundreds of empty locality pages.

## 5. Run an editorial process

Each week: choose a real user question, assign an editor, draft, check facts/rights, approve, link from a relevant public page, review feedback/search queries, then correct or retire stale content. Frequency must match review capacity. Keep draft/example campaigns labelled until real.

## 6. Measure deployed experience

Measure mobile Core Web Vitals, page/image bytes, errors and backend-independent navigation. Layout checks are not a Lighthouse performance score. Preserve image dimensions/compression, lazy loading, contrast, focus, reduced motion and usable empty/error states. Do not cache private or withdrawn media publicly for a synthetic score.

## 7. Add only supported structured data

Generic notices currently lack structured event start/end and inventory. Do not fabricate Event dates, prices, star ratings or review markup. Event schema needs validated timing/timezone/venue/availability matching visible terms. Future outbound UGC/paid links need appropriate rel=ugc/sponsored; current descriptions are text rather than arbitrary HTML links.

## 8. Improve from evidence

Review canonical coverage, genuine impressions/clicks, useful visits, server failures and complaints. Account views are not distinct verified humans. Never seed popularity, buy backlinks/fake reviews or promise guaranteed search placement. Follow [Google UGC spam guidance](https://developers.google.com/search/docs/monitor-debug/prevent-abuse) and [Search Essentials](https://developers.google.com/search/docs/essentials).
